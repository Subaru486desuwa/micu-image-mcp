# micu-image-mcp v0.3.3 — First-run Credential Setup

v0.3.3 completes the one-line installer flow by securely provisioning the Image2 API key during installation instead of leaving a newly installed MCP without credentials.

## Highlights

- Reuses an existing `MICU_API_KEY` environment variable when present and validates its format before installation continues.
- Reuses credentials already stored in macOS Keychain, Windows Credential Manager, or Linux Secret Service.
- Migrates a legacy `MICU_API_KEY` found in existing Codex/Claude MCP configuration into the system credential store, then removes the plaintext client copy.
- Prompts once for a missing API key in an interactive first-run installer, with hidden input and up to three validation attempts.
- Requires the key to start with `sk-`, be 20–512 ASCII characters long, and contain only letters, digits, `-`, and `_`.
- Keeps the default endpoint at `https://www.micuapi.ai`; custom endpoints continue to use `--baseurl` or `MICU_BASEURL`.
- Keeps API keys out of generated Codex TOML and Claude JSON configuration.
- Makes the macOS/Linux `curl | sh` bootstrap reconnect the Rust installer to `/dev/tty` so first-run credential input remains interactive.
- Retains the Windows PowerShell 5.1-compatible architecture detection introduced after v0.3.2.

## Security

- Secrets are stored through the platform-native credential backend and are never printed by the installer.
- Conflicting legacy keys in Codex and Claude configuration are rejected rather than guessed.
- Non-interactive installation never blocks waiting for a secret; credentials can still be supplied through `MICU_API_KEY`.

## Validation

- Rust unit and integration tests cover key format validation, credential migration, conflict handling, installer idempotency, and client-config redaction.
- Python compatibility/offline contract tests pass with live image requests disabled.
- `cargo fmt --check`, Clippy with warnings denied, full locked Rust tests, bootstrap syntax checks, and `git diff --check` pass before release.
- Native release workflow builds Linux x86_64, macOS arm64/x86_64, and Windows x86_64 binaries and publishes `SHA256SUMS`.

## Assets

This release publishes only the four Rust binaries and `SHA256SUMS`.
