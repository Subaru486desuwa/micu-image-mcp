# v0.6.0

## 升级方式

已安装的 MCP 不会自动更新，请重新运行安装命令。已保存的 API key 不用重新输入，macOS 可能重新询问一次钥匙串授权。

macOS / Linux：

```bash
curl -fsSL https://raw.githubusercontent.com/Subaru486desuwa/micu-image-mcp/main/scripts/install.sh | sh
```

Windows PowerShell：

```powershell
irm https://raw.githubusercontent.com/Subaru486desuwa/micu-image-mcp/main/scripts/install.ps1 | iex
```

完成后重新连接 MCP，调用 `server_info` 确认 `version` 为 `0.6.0`。Claude Desktop 普通 Chat 模式不由安装器配置，请按[兼容性指南](https://github.com/Subaru486desuwa/micu-image-mcp/blob/main/docs/claude-desktop-compatibility.md)更新。

## 默认模型升级到 GPT Image 2.6

- 新增 `gpt-image-2.6-flare` 和 `gpt-image-2.6-sunburst`。文生图默认使用 Flare，编辑、批量编辑和多图参考默认使用 Sunburst；`MICU_MODEL` 和调用时的 `model` 仍可指定其他模型。
- 2.5 模型继续可选，带 `-openai` 的旧配置和旧会话继续可用。
- 2.6 没有 `-openai` 别名。上游拒绝时直接返回错误，不会改用 2.5。升级前请确认当前凭据可以使用 2.6；不能使用时，把 `MICU_MODEL` 设为 2.5 模型即可，它同时覆盖文生图和编辑的默认模型。
- 2.6 Sunburst 与 2.5 Sunburst 一样串行执行，并使用同模型重试。
- 2.6 静态图的尺寸：1536×1024、2048×2048、3840×2160 都按请求返回；请求 1024×1024 时两次都得到 1254×1254，原因未知。此时 `notes` 会提示，`size_honored` 为 false，请以 `saved[].actual_size` 为准。

## 支持 GIF 动图

- `image_generate` 和 `image_edit` 新增可选参数 `output_format`：`png`、`jpeg`、`webp`，`gif` 仅限 2.6。省略时不发送，已有调用的请求体不变；批量编辑和多图参考没有此参数。
- 动图由提示词触发。要 GIF 时必须在 `prompt` 里明确要求动画：只传 `output_format=gif` 可能返回静态图，不传该参数也可能返回 GIF。
- `saved[]` 新增 `format`，GIF 另有 `frame_count`。格式和扩展名由文件内容决定，与请求不一致时写入 `notes`，图片仍然保存，因为这次调用可能已经计费。
- GIF 尺寸由上游决定，通常约 414×414，不保证遵循 `size`，个别结果的比例超过 3:1。`notes` 只说明实际尺寸，不会建议换用不支持 GIF 的线路。`size` 的本地校验不变：收到约 400 像素的 GIF，不代表可以请求 `400x400`。
- 帧数、帧间隔和循环由上游决定。上游收到 `frame_count`、`frame_duration_ms` 不会报错，但也不按请求生效，所以 MCP 不提供这些参数。
- GIF 不能作为编辑输入。会话里的 GIF 版本不能继续编辑，可用 `parent_revision` 选择非 GIF 版本，或转换后用 `session_id="new"` 开始新会话。
- 响应大小上限仍是 25MiB。图片经 base64 返回时，约 18.7MiB 以上的 GIF 会失败，此时上游可能已经计费；目前实测的 GIF 都不到 1MiB。

## GIF 校验

- 输出的 GIF 逐帧校验，截断或损坏的文件会被拒绝。上限为 1024 帧和 2^30 合成像素，超出画布的帧同样拒绝，防止解压炸弹。
- 校验失败发生在图片返回之后，这张图不会保存，但这次调用可能已经计费。
- 输入的 GIF 按文件头直接拒绝，不解码任何帧；损坏的 GIF 也统一报“不受上游支持”。

## 验收范围

2026-11-05 在米醋主站完成 15 次真实调用，全部返回 HTTP 200，覆盖 Flare 与 Sunburst 的生成和 PNG → GIF 编辑；另有一份 `quality=low` 的批量报告，18 次请求中 17 次成功，Flare 的 32 帧请求连接中断。上述在线结果均为候选版本，GIF 校验的最终修改之后用 23 个真实 GIF 做了离线回放，没有再发付费请求。

GIF 作为输入、GIF 的 2K/4K、`low` 以外的 `quality` 尚未验证。动图触发的两个对照各只调用一次。

本版本新增直接依赖 `gif`，它此前已是 `image` 的依赖，版本不变。正式资产平台保持 Linux x86_64、macOS arm64/x86_64、Windows x86_64；离线验收已在 Linux x86_64 通过，其余平台由 Release 工作流在原生 runner 构建、测试和 smoke。
