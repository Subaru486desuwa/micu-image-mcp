# v0.5.2

## 模型改名不再被旧映射覆盖

- 图像模型目录改为手动维护，普通工具调用和 `server_info` 不再请求 `/v1/models`。
- Flare、Sunburst 优先使用不带 `-openai` 的 ID。上游明确拒绝当前模型名称时，才用同族带后缀 ID 补试一次；旧配置、显式参数和持久会话继续兼容。
- 权限、认证、限流、余额、审核、参数、普通服务错误与成功后的下载/解析失败不触发模型切换。模型错误 code 不能覆盖消息中的矛盾原因或其他模型；New API 分组名称也不会被误当成参数。
- 标准 `gpt-image-2` 与历史质量线路 `gpt-image-2-openai` 保持独立，既有大尺寸路由、质量和并发策略不变。结果和会话记录实际使用的 ID。

## 累计包含此前未公开发布的改动

- 永久移除 Grok 图像通道，保留五个 MCP 工具及输入 schema。
- macOS 后台凭据读取禁止认证 UI；凭据不可用不阻塞 MCP 握手。显式 `credentials authorize` 与隐藏输入的 `credentials set` 分离交互授权，取消不循环重试或重写客户端配置。
- 保留当前 main 的依赖安全锁文件更新，包括 TLS 根证书/验证库以及 rand/chacha20 修补；保留已移除的 Star history 状态。

macOS 钥匙串真实 UI 和用户客户端重连仍需在 Mac 上按原生验收指南检查；其他平台的离线构建不能代替这些操作。

## 有界真实验收入口

新增 `examples/live_once.rs`，复用受控配置解析、产品凭据机制、Rust STDIO 驱动和可信 relay。显式双开关后只调用一次默认 Flare 生图，上游图像 POST 最多 2，失败不继续付费调用。输出与脱敏证据保存在 ignored `target/`，不持久化凭据、完整配置或签名 URL；用法见 [Rust-only 开发与验收](../rust-only-development.md#显式在线入口)。

正式资产平台保持 Linux x86_64、macOS arm64/x86_64、Windows x86_64；Osaka ARM64 构建用于本地验收，不作为这些平台的原生证据。本版本不包含独立开发中的自动更新器。
