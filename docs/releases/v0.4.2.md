# micu-image-mcp v0.4.2: Flare model ID compatibility

## Fix

- Text-to-image generation now defaults to `gpt-image-2.5-flare-openai`.
- All four image tools accept the new ID. The old `gpt-image-2.5-flare` ID maps to it automatically, including existing `MICU_MODEL` settings and saved editing sessions.
- `server_info`, tool guidance, the quality-matrix planner, and the usage documentation report the current ID.
- Sunburst defaults, quality parameter options, size routing, concurrency policies, the five MCP tools, and their input schemas remain unchanged.

## Dependency security

- Updates locked `rustls` from `0.23.45` to `0.23.46` and `quinn-proto` from `0.11.17` to `0.11.18`, addressing seven RustSec advisories detected by release CI.
- These are patch-level lockfile updates; dependency feature selections and public tool schemas stay unchanged.

## Upgrade

Replace the executable your client starts, then reconnect MCP. Existing client configuration, credentials, images, and session records can stay in place. Call `server_info` to confirm version `0.4.2` and the new default model.

## Validation and assets

Offline regressions exercise the real STDIO and HTTP paths for default generation, both Flare IDs, all edit tools, legacy configuration, and persisted sessions. Historical live-quality observations retain their original model IDs and dates. This update does not include paid image validation of the renamed model.

Release assets are native binaries for Linux x86_64, macOS ARM64/x86_64, and Windows x86_64, plus `SHA256SUMS`. Osaka Linux ARM64 is used for source-build validation and is not a prebuilt release asset. The previous v0.4.1 release remains available for rollback.
