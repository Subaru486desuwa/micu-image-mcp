# v0.7.1

## 升级方式

已安装的 MCP 不会自动更新，请重新运行安装命令。已保存的 API key 不用重新输入，macOS 可能重新询问一次钥匙串授权。

macOS / Linux：

```bash
curl -fsSL https://raw.githubusercontent.com/Subaru486desuwa/micu-image-mcp/main/scripts/install.sh | sh
```

Windows PowerShell：

```powershell
irm https://raw.githubusercontent.com/Subaru486desuwa/micu-image-mcp/main/scripts/install.ps1 | iex
```

完成后重新连接 MCP，调用 `server_info` 确认 `version` 为 `0.7.1`。Claude Desktop 普通 Chat 模式不由安装器配置，请按[兼容性指南](https://github.com/Subaru486desuwa/micu-image-mcp/blob/main/docs/claude-desktop-compatibility.md)更新。

## 新增 2.6 OpenAI 线路

- 新增模型 `gpt-image-2.6-flare-openai` 和 `gpt-image-2.6-sunburst-openai`，需要在调用时传 `model`。默认模型不变，仍是 `gpt-image-2.6-flare` / `gpt-image-2.6-sunburst`。
- 计费方式不同：米醋按 token 计费，不带后缀的 2.6 按次计费。2026-11-19 的公开倍率为模型倍率 12.5、补全倍率 6；`quality=low` 的 1024×1024 一张约 824 个输出图像 token，`quality` 越高输出 token 越多。实际价格以米醋后台为准。
- 它们是独立模型，不是别名：MCP 原样发送这两个 ID，被上游拒绝时直接报错；不带后缀的 2.6 被拒绝时也不会改用它们。
- `quality` 可选 `auto`、`low`、`medium`、`high`，不接受 `xhigh`、`max`。`output_format` 可选 `png`、`jpeg`、`webp`，不支持 `gif`。
- 请求不发送 `response_format`，上游以 `b64_json` 返回图片。
- 调度随家族：Flare 线路 1K 下 `n>1` 最多 5 并发；Sunburst 线路逐个串行，`image_batch_edit` 相邻图片间隔 1.5s。2K/4K 沿用 `n=1` 和跨进程锁排队。
- 两者都可用于生成、编辑、批量编辑和多图参考。

`server_info` 的 `available_models`、`quality_values_by_model`、`output_format_values_by_model` 增加这两个模型，并新增 `openai_route_live_observation_2026_11_19` 记录本次实测。

## 未改变

带 `-openai` 的 2.5 ID 仍按 v0.5.2 的旧 ID 规则处理：改写为不带后缀的 2.5 ID，只有上游明确拒绝时才用带后缀 ID 补试一次。米醋目前对 2.5 的 `-openai` 也按 token 计费，本版本不改变这条规则。

## 验收范围

2026-11-19 在米醋主站，按米醋画图 HTML 的请求格式用独立脚本各调用一次：`gpt-image-2.6-flare-openai` 生图、`gpt-image-2.6-sunburst-openai` 单图编辑，均为 1024×1024、`quality=low`、省略 `response_format`，都返回 HTTP 200 和 1024×1024 PNG，内容与提示词一致。

本次没有通过 MCP 发起真实调用。MCP 侧由离线测试覆盖：路由表（模型 × 尺寸档位的重试、并发和 `response_format`）、各 `quality` 档位实际发送的字段，以及被拒绝时不补试其他模型。未覆盖：`low` 以外的 `quality`、`jpeg` / `webp`、2K/4K、mask 和多图参考。

正式资产平台保持 Linux x86_64、macOS arm64/x86_64、Windows x86_64；离线验收已在 Linux x86_64 通过，其余平台由 Release 工作流在原生 runner 构建、测试和 smoke。本版本没有新增或升级依赖包。
