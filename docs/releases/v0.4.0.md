# micu-image-mcp v0.4.0 — Claude compatibility and editing sessions

Claude Desktop Code mode could connect to the MCP process but expose zero tools because modern catalog responses lacked required cache metadata. v0.4.0 adds protocol-aware `ttlMs: 0` and `cacheScope: private` to tools, prompts, resources, and resource-template catalogs while preserving legacy responses. This fixes issue #11.

## Editing sessions

- Generation and reference editing share explicit persistent session IDs. Keep the returned ID for subsequent edits, request a new session for another subject, and reuse the earlier ID to return to its image.
- Successful revisions store their selected image, instruction history, and constraints. Explicit parent revisions support branches; failed requests do not advance history.
- Session locks, bounded records, atomic writes, path confinement, image validation, and secret redaction protect the stored state.
- The same five public tools remain. Optional session fields preserve stateless callers.
- The Rust catalog includes the currently supported flare/sunburst models and compact tool guidance for native Claude Code and DeepSeek harnesses. The Python implementation remains the frozen compatibility reference.

## Updating Claude Desktop

Install the updated binary and reconnect MCP. Desktop Code mode uses the Claude Code user configuration; ordinary Chat mode needs its separate `claude_desktop_config.json` entry. See [the compatibility guide](../claude-desktop-compatibility.md) for both modes.

The offline regression reproduces zero tools by removing only the two cache fields, then verifies that the real Claude Code client registers all five tools and successfully calls `server_info` with the fixed responses. Desktop window acceptance is performed separately by the user.

## Validation and assets

Osaka validation includes the full Python offline suite, locked Rust tests, modern/legacy protocol regressions, formatting, strict Clippy, frozen-reference and Rust contracts, and a release build. Native CI builds Linux x86_64, macOS arm64/x86_64, and Windows x86_64 binaries with SHA-256 checksums. No paid requests are required for this compatibility regression.
