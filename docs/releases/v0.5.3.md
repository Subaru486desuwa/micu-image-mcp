# v0.5.3

## 大尺寸批量编辑按说明串行

- `image_batch_edit` 处理 2K/4K 时，`gpt-image-2.5-flare` 等标准线路改为逐张串行，相邻图片间隔 1.5s，返回的 `concurrency` 为 1。此前只按模型判断，2K/4K 的 Flare 批次会以 5 并发进入队列，与 `server_info` 能力矩阵中“≥2k 逐张串行 + 1.5s gap”的说明不一致。
- 1K 标准线路的 5 并发、Sunburst 与历史质量线路的串行策略不变。大尺寸请求仍通过进程内与跨进程锁排队，实际上游吞吐基本不变。

## 模型路由集中维护

- 同一模型在同一尺寸下的实际模型 ID、可选 quality、重试计划、并发上限和 `response_format` 协商，统一由一处路由规则决定；四个图像工具不再各自推断。
- 公开 schema、五个 MCP 工具、参数校验顺序、报错文字、重试计划和输出 JSON 形状保持不变。
- 新增覆盖全部模型 × 尺寸档位的路由表测试，并校验 `server_info` 中 `quality_values_by_model` 与实际校验规则一致。

正式资产平台保持 Linux x86_64、macOS arm64/x86_64、Windows x86_64。本版本不包含付费在线验收；离线 STDIO、HTTP fixture 与 smoke 验收已在 Linux x86_64 通过，其余平台由 Release 工作流在原生 runner 构建、测试和 smoke。
