# v0.4.1：把单次生图接成连续创作

## 先把“记忆”变成可以验证的行为

目标场景是小猫跳伞、修改飞行装备、独立生成海景、回到小猫改日落。
对应两条图片会话 A/B，成功版本依次为 A·r1、A·r2、B·r1、A·r3。

MCP 根据显式 `session.id` 关联图片，不使用全局“最近一张”，也不依赖上游的聊天 conversation。
客户端或模型负责选择 ID；MCP 保存对应的成功图片、指令与有效约束。
后续编辑上传所选版本图片，带上该分支的成功历史和本轮指令。重启后保留 ID、输出根和图片即可继续。

离线测试检查上传图片哈希、设置继承、约束覆盖、独立主题、分支祖先、失败不推进、跨进程锁和凭据脱敏。
本地记录有版本数与大小上限，图片独立落盘；没有整体磁盘配额或自动过期清理。
详见[连续编辑](multi-turn-editing.md)、[存储管理](session-storage.md)。

## 让真实 harness 自己选择会话

使用 OpenCode + DeepSeek Flash、Claude Code + Sonnet 4.6、Claude Code + DeepSeek V4 Pro 三种组合。
文字推理由真实客户端和模型完成，图片接口使用本地替身，测试只观察工具选择和上下文管理。

最初 DeepSeek 有一个场景省略所有可选 `session_id`。把“新主题必须新建、同主题编辑复用返回 ID”
放到简洁工具说明最前面后，三种组合在两组四轮固定场景中通过 24 个路由检查。
这些小规模场景证明当前调用链可工作，不保证任意模型、提示或超长聊天都能正确选择 ID。

五个工具说明总量从 23,127 降到 3,256 字节；DeepSeek 首轮工具上下文从 9,924 降到 3,607 tokens。
常驻 OpenCode 服务也减少了重复启动开销。固定 200 ms 本地接口替身的独立会话并发，
四任务从约 953 ms 降到约 248 ms；调整到 1/2/4 个工作线程未见可测收益，保留运行时默认设置。
这些数据不代表真实图像服务的渲染时间。[原生 harness 记录](harness-validation.md)包含环境和复跑方法。

## 用真图检查“记得住”与“画得准”

OpenCode + DeepSeek Flash 再通过 Osaka 的 Rust MCP 调用米醋主站，得到四步图中的实际结果。
独立海景第一次上游返回 400，调整提示后重试成功；失败轮次没有提交版本。

人工查看发现第二步把软翼滑翔伞画成了硬质三角滑翔翼。随后在同一会话补充软翼、翼室、
吊绳和无金属支架的明确约束，得到 A·r4，保留了同一只小猫、日落与构图。
这个额外精修由人工发起，没有计入 24 个模型自动路由检查。

## 复刻 Claude Desktop 的零工具故障

[issue #11](https://github.com/Subaru486desuwa/micu-image-mcp/issues/11) 的截图显示进程已经连接，
但目录响应缺少 `ttlMs`、`cacheScope`，导致客户端拒绝 tools/list，面板显示零工具。

用真实 Claude Code 2.1.295 和本地模型响应替身，将服务响应中的这两个字段单独删除，
即可稳定复刻四次 tools/list 重试、零工具、无法调用 server_info。
保留完整字段后，首次读取目录即注册五个工具，并成功调用 server_info。
修复按每个请求的协议版本生效：新协议填入 `ttlMs=0`、`cacheScope=private`，旧协议保留原格式。
这两个字段属于目录缓存，不控制图片会话保存时间。[兼容性指南](claude-desktop-compatibility.md)提供完整复跑方法。

## 让干净环境和发布包都通过

首次 CI 又暴露了两处测试环境差异：新版 Pydantic 的帮助链接由 2.13 变为 2.14，
macOS 的 `/var` 别名和 Windows 路径标准化也让手工注入的测试根目录不匹配。

只在冻结参考比较中归一化帮助链接版本，并验证错误类型、输入值和 MCP 错误标志仍严格比较；
图片会话测试夹具则按生产配置的方式标准化根目录。路径保护逻辑保持原样。
v0.4.0 发布候选因此取消，最终发布 v0.4.1。
