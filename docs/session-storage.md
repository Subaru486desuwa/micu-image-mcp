# 图片会话在用户电脑上的保存与管理

会话记忆是 MCP 保存的本地 JSON 文件，不是上游的 token/KV 缓存。
每次成功只记录当前指令、有效约束、设置和图片路径，不把图片或完整 base64 放进 JSON。
图片本身独立保存，每个成功版本通常新增一张图片。

## 保存位置

| 内容 | 位置与用途 |
| --- | --- |
| 会话记忆 | `MICU_SAVE_DIR_ROOT/.micu-sessions/edit_<id>/revision-<n>.json` |
| 图片 | 正常输出目录，由 `saved.path` 返回；`MICU_SAVE_DIR` 必须位于输出根目录内 |
| 并发锁 | 会话目录的 `.lock`、`~/.cache/micu-image/bigsize.lock`；锁文件不保存图片或历史 |
| 请求临时文件 | 请求期间使用的输入快照与输出临时文件，正常完成、失败和取消时释放 |

未自定义时，输出根目录是 `~/Pictures/micu-out`。客户端配置可能覆盖它，先通过 `server_info`
查看实际目录。改动根目录后，旧会话不会自动迁移；记录里的图片路径是绝对路径。
进程被强制终止或机器断电时可能遗留临时文件，当前没有启动时自动扫除功能。

## 占用大小

2026-10-09 在 Osaka 的真实 Rust MCP 与本地 HTTP 替身上测量，图片费用为零。
以下只统计版本 JSON，不含目录、锁和图片；数据块占用依文件系统变化。

| 会话约束示例 | 成功轮数 | JSON 合计 | JSON 数据块占用 |
| --- | ---: | ---: | ---: |
| 人物、衣服、背景、构图等短约束 | 20 | 11.1 KiB | 80 KiB |
| 同上 | 128 | 71.4 KiB | 512 KiB |
| 约 6440 字符的较长约束 | 20 | 386.4 KiB | 400 KiB |
| 同上 | 128 | 2.42 MiB | 2.50 MiB |

每条记录硬上限 256 KiB，每会话最多 128 个版本，因此版本 JSON 的理论总量上限为 32 MiB。
有效约束在每轮记录中保存完整当前值，较长约束会重复占用空间；历史指令每轮只新增本轮内容。

图片通常是主要占用：如果每张 1.5 MiB，20 个成功版本约 30 MiB，128 个版本约 192 MiB。
这只是容量估算，实际以 `saved.size_bytes` 为准。目前没有会话总数上限、整体磁盘配额、TTL 或自动清理。
没有成功版本的初始请求也可能留下空会话目录和锁文件。

## 当前如何管理

macOS/Linux 可通过 Finder、文件管理器或终端查看实际输出目录。
Finder 用 `Command+Shift+.` 显示 `.micu-sessions`。Windows 可在资源管理器地址栏直接进入该目录。

```bash
# 按 server_info 返回值替换；以下是默认路径。
micu_root="$HOME/Pictures/micu-out"
du -sh "$micu_root" "$micu_root/.micu-sessions"
```

- 要继续编辑或保留回滚：保留会话目录、全部版本 JSON 和对应图片。先结束正在执行的请求再归档。
- 已结束且只需要作品：先复制最终图片到作品目录，再将该会话目录及确认不再需要的中间图片移到归档或废纸篓。
- 只清除记忆：归档整个 `edit_<id>` 目录；图片仍保留，可通过图片路径和 `session_id="new"` 重新开始。
- 恢复归档：将会话目录及图片恢复到原位置，再使用原 ID。只迁移 JSON 或只删除祖先 JSON 会破坏恢复链路。

当前没有会话管理面板或清理 CLI。不要将整个输出根目录当作可随时删除的普通缓存；它包含用户作品。
不要在请求运行时删除锁文件，否则新的请求可能绕过原锁而同时进入上游。

## 在线质量档位验证

这里的参数名是 `quality`，不是 Codex 的 `reasoning_effort`。
MCP 当前对 2.5 模型接受 `auto/low/medium/high/xhigh/max`，对旧 Image2 模型接受
`auto/low/medium/high`；接口接受不等于上游线路接受。

可复跑的验收程序只连接固定米醋域名，先检查凭据和可用模型，再逐项调用 Rust MCP 的生成、编辑工具。
程序用本机回传代理统计实际上游图片 POST，包括重试；凭据只保留在内存，不进入参数、日志或报告。
每项独立开始会话，记录成功、错误、耗时、尺寸、图片大小与对应会话，避免失败的约束污染其他项。

```bash
# 仅列出计划；不读凭据，不发网络请求。
.venv/bin/python -m tests.contract.live_quality_matrix --plan

# 已授权的在线验证：读取进程 MICU_API_KEY，或 Codex 的 micu-image 环境配置。
# 主站凭据必须有效；用新目录保存报告，防止覆盖已有证据。
MICU_RUN_LIVE_TESTS=1 .venv/bin/python -m tests.contract.live_quality_matrix
```

四个 MCP 模型均可用时共有 48 项；程序按当前凭据实际可用的模型缩减矩阵，覆盖省略质量参数和所有声明档位。
按照用户给出的 0.1 元/次，48 次基础请求名义金额为 4.8 元；重试会增加请求数，实际扣费须以站点账单为准。
鉴权失败时停止，不继续产生图片请求。

2026-10-09 更新凭据和主站地址后，在 Osaka 完成 38 项 1K 生成/单图编辑验证（38 次上游 POST，零重试）：

| 模型 | 省略 | auto | low | medium | high | xhigh | max |
| --- | --- | --- | --- | --- | --- | --- | --- |
| gpt-image-2.5-flare | 成功 | 成功 | 成功 | HTTP 400 | HTTP 400 | HTTP 400 | HTTP 400 |
| gpt-image-2.5-sunburst | 成功 | 成功 | 成功 | HTTP 400 | HTTP 400 | HTTP 400 | HTTP 400 |
| gpt-image-2 | 成功 | 成功 | 成功 | 成功 | 成功 | MCP 不接受 | MCP 不接受 |

两个 2.5 模型的失败均明确提示 GPT Image 2.5 supports only low。省略/auto 返回成功，
没有证据证明 auto 的实际工作量高于 low。本次凭据模型列表只有以上三个模型，没有 gpt-image-2-openai。

22 项成功结果均保存为有效的 1024x1024 PNG，共 7,313,153 字节，平均每张约 325 KiB。
额外复用其中一张完成两次连续修改，每轮重启 MCP：白背景蓝杯 → 绿背景蓝杯 → 绿背景黄杯，
人工查看确认最后一轮保留上一轮背景、桌面和构图。该三版本会话 JSON 共 1669 字节。
全部共 40 次图片 POST（24 次成功、16 次质量参数被拒绝），按 0.1 元/次名义计算 4 元；
未核对后台实际扣费。所有验收通过 Rust MCP 执行，图片和无密钥报告保存在被 Git 忽略的 tests/reports 下。
